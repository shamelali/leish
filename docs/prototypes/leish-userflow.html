Platform reference

Leish User Flows

leish.my · All roles · Last updated May 2026

👤 Customer
💄 Artist (MUA)
🏛️ Studio manager
🔐 Admin

Discovery

1
Land on leish.my
Homepage → hero, categories, featured artists, AI concierge widget, style quiz
↓
2
Browse artists /artists
Filter by specialty, state, district. Cards show name, rating, starting rate, portfolio thumbnail.
↓
3
View artist profile /artists/[slug]
Portfolio gallery with lightbox, services + pricing, availability calendar, sticky book bar, in-app chat

Booking

4
Select date, time, service
BookingCalendar checks MUA availability in real time — blocks taken slots
↓
5
Register or sign in required to proceed
/register → role: customer → auto sign-in → redirected back to booking
↓
6
Pay via Billplz
POST /api/payments/billplz/create → redirect to Billplz hosted payment page
↓
7
Payment success /booking/success
Reads billplz[paid] param → verifies with /api/payments/status → shows confirmation + booking details

Post-booking

8
In-app messaging
ArtistChat on profile page — enforces on-platform comms, off-platform detection active
9
Leave review
POST /api/reviews after booking completed — rating + comment, visible on artist profile
⚠
Customer dashboard not yet built — no /account page to manage bookings after sign-in. Customers land on homepage with no post-login destination.

Registration

1
Register /register
Select role: Makeup Artist → email + password + full name + phone → submit
↓
2
Auto sign-in → redirect fixed
signUp() → signInWithPassword() → 800ms wait for DB trigger → getPostSignInPath("artist") → /artist
↓
3
Layout guard → onboarding fixed
/artist layout checks for provider row → none yet → redirect("/artist/onboarding")
↓
4
Onboarding wizard /artist/onboarding
Step 1: display name + location → Step 2: specialties → Step 3: bio + experience → Step 4: services + pricing
↓
5
POST /api/onboarding/artist
Creates provider row with is_active: true — live immediately, no approval needed
↓
6
Artist dashboard /artist
Stats, upcoming bookings, loyalty tier card, pro upgrade prompt

Dashboard features

→
Profile & services /artist/profile
Edit bio, specialties, services + pricing. Upload portfolio photos to Supabase storage.
→
Availability /artist/availability
Set recurring weekly schedule. Block specific dates. Syncs with BookingCalendar on public profile.
→
Bookings /artist/bookings
Upcoming bookings — confirm or cancel. Brevo reminder emails sent via cron 09:00 daily.
→
Payments /artist/payments
Payout history, earnings stats. Escrow released after booking completed.
→
Reviews /artist/reviews
All client reviews received. Rating average updates on public profile.
→
Pro upgrade /pro/upgrade
Unlock higher client limit, featured placement in browse, analytics dashboard.

Returning sign-in

↩
Sign in → /artist
Layout guard: provider row exists → dashboard. No provider row → back to /artist/onboarding.

Registration

1
Register /register
Select role: Studio Manager → email + password + full name + phone → submit
↓
2
Auto sign-in → onboarding fixed
New studio_manager always → /studios/onboarding (not dashboard). Bypasses dashboard guard.
↓
3
Studio onboarding wizard /studios/onboarding
Step 1: studio name + type → Step 2: location + address → Step 3: bio + team size → Step 4: services + rate → Step 5: operating hours
↓
4
POST /api/onboarding/studio 500 error
Creates provider row with is_active: true. Currently returning 500 — check NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY in Vercel env vars.
↓
5
Studio dashboard /studios/dashboard
Bookings overview, stats, team management, studio status (live / pending)

Customer books a studio

→
Browse studios /studios
Studio grid. "Browse spaces →" links to /studios/gallery (new — shows rooms + media)
→
Studio gallery /studios/gallery
Studio tabs, media grid with lightbox, room cards with capacity + hourly rate + book button
→
Book a space /studios/[slug]/book
Calendar, room selector, payment via Billplz. Same payment flow as MUA booking.

Returning sign-in

↩
Sign in → check studio row
Has studio row → /studios/dashboard. No studio row → /studios/onboarding.
⚠
500 on studio onboarding submit: Vercel → Settings → Environment Variables → delete NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY if present. NEXT_PUBLIC_SUPABASE_ANON_KEY is the correct key.

Access

1
Sign in → /admin admin role only
profiles.role = "admin" required. studio_manager access removed. Redirects to / if wrong role.

Provider management

→
Providers /admin/providers
View all MUAs and studios. Toggle is_active to suspend or reinstate. View full profile.
→
Placeholders /admin/placeholders
Seed demo MUA profiles before real supply is onboarded. Use to test browse page.

Platform oversight

→
Bookings /admin/bookings
All platform bookings — status, amounts, dispute flags, customer + artist info
→
Payments /admin/payments
Billplz webhook health, payout tracking, escrow status per booking
→
Moderation /admin/moderation
Off-platform contact violations flagged by concierge guardrails and in-app chat detection
→
System monitoring /admin/monitoring
Webhook health checks, cron job status, Sentry error feed

Background jobs

⏰  
booking-cleanup — 06:00 daily — cancels expired unpaid bookings
reminders — 09:00 daily — sends Brevo reminder emails to MUAs + customers
webhook-monitor — 12:00 daily — checks Billplz webhook health
